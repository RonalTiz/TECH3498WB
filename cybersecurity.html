Threat Review

STRIDE Threat Assessment

Key risks for a static portfolio hosted on GitHub Pages and practical ways to reduce them.

Spoofing
Client-Side Login

Login state stored in sessionStorage can be changed by a visitor. It is suitable for a demonstration, not protecting private information.

Tampering
External Dependencies

A compromised third-party CDN could affect site visitors. Use Subresource Integrity where supported, and keep dependencies current.

Repudiation
Limited Audit Visibility

The site has no application server for recording detailed user actions. Avoid relying on it for audit trails or incident investigation.

Information Disclosure
Public Repository

Website source and repository history may be public. Do not commit passwords, API keys, or sensitive personal information.

Denial of Service
Service Availability

Traffic spikes or hosting-service issues could make the site unavailable. Keep assets lightweight and maintain a copy of the site files.

Elevation of Privilege
Direct Page Access

Static pages can be requested directly by URL. Treat admin pages and client-side checks as demonstrations, not security boundaries.

Security Overview

How Security Is Implemented

Security controls and limitations across this static GitHub Pages portfolio.

Frontend

Bootstrap CSS and JavaScript use Subresource Integrity (SRI). Chatbot messages from visitors are displayed as text rather than interpreted as HTML.

Web Server

GitHub Pages hosts the static files and supports HTTPS to encrypt traffic in transit. It does not run this site's login checks or provide server-side access control.

Application Layer

Site features run in browser-side JavaScript. Because visitors can inspect or modify that code, it cannot securely enforce protected actions.

Database

This portfolio does not connect to a database or store database records.

Authentication & Authorization

The demo login uses credentials checked in browser code. The security page checks a session-storage flag. These client-side checks can be bypassed and do not protect private content.

Encryption

HTTPS encrypts data in transit when the site is visited over HTTPS. Theme preferences and login flags in browser storage are not encrypted secrets.

Session Management

The demo stores login state in sessionStorage, which is controlled by the visitor's browser and should not be treated as a secure session.

Input Validation

Login fields use required form attributes, and chatbot input is trimmed before processing. These are browser-side checks; there is no backend validation.

PRO TIP
Cybersecurity Tip of the Day

Enforce Multi-Factor Authentication (MFA) & Use a Password Manager: Over 80% of data breaches involve compromised or reused passwords. Enabling MFA (preferably using an authenticator app or hardware FIDO2 key rather than SMS) blocks more than 99% of bulk automated credential attacks according to CISA and Microsoft threat intelligence. Pair this with unique, generated 16+ character passphrases for every account.
