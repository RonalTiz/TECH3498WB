Does an IDS Learn Attack Behavior—or Network Identity?

Testing whether intrusion-detection models generalize to source hosts they did not encounter during training.

NICA Dataset Three CV Strategies Two Classifiers
Overview Dataset EDA findings Method Results Interpretation Resources
Research question

The security problem

An intrusion-detection model may score highly when training and validation records contain traffic from the same hosts. It may have learned endpoint-specific clues rather than patterns that transfer to unfamiliar systems.

Does the model recognize malicious traffic behavior, or does it depend on IP addresses and other familiar data patterns?

This project investigates a possible “accuracy illusion” by comparing ordinary random cross-validation with validation folds that keep duplicate records or source hosts together.

What the experiment tests

  • Whether direct IP features affect model scores.
  • Whether duplicate records cross CV folds.
  • How models perform on source IPs held out from training.

Data

Dataset and prediction target

The study uses the Network Intrusion and Cyberattack Dataset (NICA) from Kaggle. Its flow records contain endpoint, protocol, connection, byte, packet, DNS, HTTP, SSL, and other traffic fields.

Prediction task

The primary task is binary classification using label:

  • 0 = normal traffic
  • 1 = malicious traffic

The dataset also includes type, which identifies the traffic category. It was excluded from model inputs to prevent target leakage.

Label balance

Malicious 161,043 · 76.3%
Normal 50,000 · 23.7%

Because the classes are imbalanced, accuracy alone would not provide a complete picture of model performance.

Category counts: The type target has 50,000 normal records, 20,000 records each for backdoor, DDoS, DoS, injection, password, ransomware, scanning, and XSS, plus 1,043 MITM records.
Exploratory data analysis

What the dataset reveals

Repeated records

  • 20,569 exact duplicate rows (9.75%).
  • 27,739 rows belong to groups with identical input features.
  • No duplicate-feature group had conflicting binary labels.

Random splits can put identical feature records in both training and validation data. The duplicate-group split keeps those records together.

Missing-like values

  • The initial audit reported no blank or NaN values.
  • Text fields use "-" as a placeholder for absent or inapplicable information.
  • For example, ssl_subject and ssl_issuer each contain 211,032 dash placeholders.

Source hosts and networks are associated with labels

192.168.1.0/24 204,550 flows; 78.7% malicious
32 source IPs had only normal flows
11 source IPs had only malicious flows

The remaining eight source IPs had both classes. Several busy hosts had attack rates near 100%, while others had rates near zero. This is evidence of a possible identity shortcut, but it does not prove that every model uses one.

Rates from small groups are less reliable than rates supported by many records. The dataset has only eight source networks, and most records come from one network.

Numeric correlations: A numeric correlation analysis and heatmap are not included in the notebook results provided. No specific numeric correlation findings are claimed here.
Methodology

How the models were tested

The notebook compares two feature sets, two classifiers, and three cross-validation strategies. Preprocessing is fitted within each training fold.

Feature sets

  • IP-included: retains source and destination IP address columns.
  • IP-stripped: removes both direct IP address columns.
  • Both exclude label, type, and derived source-network fields.

Removing direct IP fields does not remove every possible indirect identifier from the remaining features.

Preprocessing

  • Replace text placeholders "-" with missing values.
  • Impute numeric values using the training-fold median.
  • Fill missing categorical values and one-hot encode them.
  • Group infrequent categories using a minimum frequency of 10.
  • Standardize numeric features within the pipeline.

Classifiers

  • Logistic Regression: a comparatively simple baseline.
  • LightGBM: a gradient-boosted tree model that can learn nonlinear patterns.
  • Both use class weighting to account for the label imbalance.

Cross-validation strategies

  • Random stratified: maintains class proportions; hosts and duplicate records may cross folds.
  • Duplicate-group: keeps identical feature records in the same fold.
  • Source-IP-group: holds out complete source IPs from training.
Why compare the splits? Random cross-validation is a conventional benchmark. Duplicate-group and source-IP-group evaluation are more demanding tests of whether the model transfers beyond repeated records and familiar source hosts.

Security interpretation

What the results do—and don’t—show

What the experiment supports

  • Random-split scores were almost perfect, but random CV allowed duplicate feature records to appear across folds.
  • Duplicate-group CV also produced very high scores, so duplicate overlap alone does not explain the results.
  • Models remained strong in source-IP-grouped evaluation after direct IP columns were removed. This suggests the dataset contains predictive signal beyond those IP addresses.

Important limitations

  • Source-IP folds vary in size and class balance, and the dataset contains only 51 source IPs.
  • Holding out source IPs within one dataset is not the same as testing on an independent network.
  • Removing IP addresses does not rule out indirect identifiers in other features.
  • The current models predict the binary label, not attack category; they do not show which attack types are hardest to detect.

Security takeaway

The dataset shows strong associations between source-host identity and attack labels. IP-stripped models still performed strongly when source IPs were held out, which is encouraging, but does not prove that the models learned general attack behavior. Evaluation on a genuinely independent network is needed before making claims about real-world performance.

False positives

Benign flows flagged as attacks can consume analyst time, create alert fatigue, and disrupt legitimate activity.

False negatives

Missed attacks can allow harmful activity to continue undetected. The appropriate balance depends on the threat, operating threshold, and response process.
