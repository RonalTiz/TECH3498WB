Network Transport and Applications

This report describes how ICMP, UDP, and TCP appear in packet captures and how application protocols use them. Replace bracketed fields with values from your capture or account review.

Security note: Capture only traffic you are authorized to inspect. Telnet, FTP, and basic email protocols can expose data without encryption. Use assigned lab systems and accounts, and do not place real credentials or private account information in a report.

Lab 3.1 - Network transport

Lab A - Network communication analysis

Question or observationResponse
What packet types are sent during a ping?For an IPv4 ping, the capture shows ICMP Echo Request packets followed by ICMP Echo Reply packets. Address Resolution Protocol (ARP) packets may appear first if the sender needs to learn the gateway's Ethernet address.
What is the Ethernet broadcast address?ff:ff:ff:ff:ff:ff
Which appears first in the Ethernet II header, source or destination?Destination appears first, followed by source and the EtherType field.
What else is in the Ethernet II header?The source MAC address, destination MAC address, and EtherType identifying the payload protocol.
What fields are in an ARP message?Hardware type, protocol type, hardware address length, protocol address length, operation (request or reply), sender hardware and protocol addresses, and target hardware and protocol addresses.
Do all ARP fields have known values in a request?No. In a request, the target hardware address is typically unknown and represented as all zeroes. The sender fields and target protocol address identify who is asking and which IPv4 address it wants to resolve.
How does an ARP reply differ from the broadcast request?The request is normally sent to the Ethernet broadcast address and asks who owns a target IPv4 address. The reply identifies the target's MAC address and is usually sent directly back to the requester.
What protocol does ping use?ICMP carries IPv4 Echo Requests and Replies. For IPv6, the corresponding messages use ICMPv6.
What source and destination ports appear in the DNS over UDP packet?Destination port is usually 53. The source port is an ephemeral client port and varies; record the captured values: source [source port], destination [destination port].
What is the UDP checksum?The checksum is calculated from the UDP header and data (and an IP pseudo-header). Record the value shown in the captured packet: [UDP checksum]. It varies by query and capture.
What does cat /etc/passwd display on a Unix-like system?It displays account records such as username, a password-field marker, user ID, group ID, descriptive field, home directory, and login shell. On modern systems, password hashes are stored separately in a protected shadow file.
What source and destination ports appear in a Telnet TCP packet?Telnet conventionally uses destination port 23; the client source port is ephemeral. Record the packet values: source [source port], destination [destination port].
What is the TCP checksum?TCP includes a checksum over its header and data plus an IP pseudo-header. Record the displayed value from the selected packet: [TCP checksum].
How do TCP and UDP headers differ?Both include source and destination ports and a checksum. TCP also includes sequence and acknowledgment numbers, flags, a window size, and options to support connection setup, ordering, acknowledgments, and retransmission. UDP has a shorter header with a length field and no built-in connection or delivery guarantees.

Lab 3.2 - Network applications

Lab A - File transfer and web traffic

Question or observationResponse
Does SSH File Transfer appear as FTP in Wireshark?No. SFTP is a file-transfer subsystem carried over SSH, usually over TCP port 22; it is distinct from FTP. The capture may identify SSH and TCP rather than FTP.
What other protocols may appear besides ARP and TCP?Depending on the activity and network, captures may include DNS, SSH, TLS, ICMP, DHCP, or IPv6 neighbor discovery. Record the protocols actually visible: [protocols observed].
What source and destination ports appear in the SSH packet?SSH normally uses destination port 22; the client source port is ephemeral. Record the values shown in your packet: source [source port], destination [destination port].
Does an HTTPS visit appear as HTTP in the capture?Normally no. HTTPS traffic is protected by TLS, so Wireshark generally identifies TLS over TCP port 443 rather than readable HTTP application data.
What source and destination ports appear in the web connection?For HTTPS, the server destination port is usually 443; the client source port is ephemeral. Record the capture values: source [source port], destination [destination port].
What is the TCP checksum for the web packet?Record the value displayed for the selected TCP segment: [TCP checksum]. It changes from packet to packet.

Lab B - Email protocols

Question or observationResponse
What message may the mail server return?The server returns a status response indicating whether it accepted or rejected the message. Record the exact response code and text shown: [server response].
How can unauthenticated or unencrypted email submission be abused?If a server permits relaying without adequate authentication, it can be abused to send spam or forged messages. Unencrypted SMTP can expose message contents and credentials in transit. Authentication, TLS, relay restrictions, and sender-domain checks reduce these risks.
What changes when a message is submitted with a different sender address?The visible From or envelope sender may differ from the first message, depending on the mail client and server. Server-added Received and authentication headers can also differ. Record the header fields observed: [header differences].
Can the true sender always be identified from the From field?No. The From field can be forged. Received headers, server logs, and SPF, DKIM, and DMARC authentication results can help trace or validate a message, but a conclusive identity may require trustworthy mail-server records.
